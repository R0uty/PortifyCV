# v1.2.0 roadmap — template design system, builder usability, Word export

**Date:** 2026-09-09
**Branch:** `v1.2.0`
**Status:** design — awaiting review before implementation plans are written

This is the roadmap doc for the v1.2.0 cycle. It scopes three sub-projects
and sequences them. Sub-projects **A** and **B** are specified here in
depth; **C** is scoped here and gets its own detailed spec later (its key
decision depends on A1's output).

Driver, stated by the user: **the templates don't look good enough.** Not
user complaints, not competitor parity — a quality-bar problem. So the work
starts by defining the bar, not by adding more.

---

## Context: what exists today

**16 templates.** 14 have a bespoke `*Showcase.jsx` + `src/styles/templates/*.css`;
2 (Minimalist, Tech Executive) render only through the shared flat renderer
(`CVPreview.jsx` + `shared.jsx`). Every template also has a flat-renderer
config (`src/components/templates/<id>.js`) used in ATS-friendly mode.

**No written design language.** Each template was authored and judged by
eye, then patched reactively — recolor Executive indigo→gold, restyle
Modern Professional against a dropped-in mockup, add Classic, add Modern
Orange. The `portifycv-modern-orange-template` work-log memory is the
closest thing to institutional knowledge, and it's a list of bug
post-mortems, not a spec.

**The builder is mature.** The `todo.md` backlog (54 items, v1.0→v1.1.16)
is essentially exhausted — one open item, and it's CI ops. A walk-through
on 2026-09-09 found the editor genuinely polished: per-section collapse,
ATS panel, nav rail sync, inline validation, appearance presets, a real
template gallery modal.

**Word export does not exist.** Export menu is PDF (html2canvas + jsPDF,
worker-based, mature) / HTML / JSON.

**Hard constraints (unchanged):** no backend; bilingual `en`/`fi` inline;
`CvData` has no per-skill rating and no date-of-birth field; html2canvas
can't render `background-clip:text`, `clip-path`, `oklch`/`color-mix`,
un-`data-export-ignore`d `filter:blur()`, or CSS animations on the export
clone (all learned the hard way — see the work-log memory).

## A. Template design system + quality pass

### A.0 The problem, precisely

From the 2026-09-09 visual pass over all 16 (demo CV, non-ATS, desktop
preview):

1. **No shared design language.** Type sizes, color usage, section-heading
   treatment, skill rendering, and URL formatting are decided per-template.
   The Modern Orange name-fragmentation bug (memory) traces directly to an
   ad-hoc `2.4rem` name size no rule constrained.

2. **A house cliché formed by default, not choice.** "Colored icon badge +
   SECTION HEADING" appears on Developer, Modern Professional, Executive,
   Graduate, Modern Orange, Portfolio, Modern Timeline, Navy Professional,
   Quadrant, Tech Executive — 10 of 16 (grep-verified in Task 1; the
   original visual pass miscounted Colorful Compact, which uses a dot).
   Templates vary by *accent hue*, far less by *structure*.

3. **Shared primitives applied inconsistently.** `formatLinkDisplayValue()`
   (strips `https://`, trailing slash) already exists in `src/utils/shared.js`
   — but **Compact, Navy Professional, Modern Timeline, and the flat
   renderer** don't call it, so they render raw `https://linkedin.com/in/…`
   that wraps across 2–3 lines. Verified by grep.

4. **Color discipline is uneven.** Modern Professional / Modern Orange /
   Developer (post-restyle) confine the accent to wayfinding. Creative,
   Executive, and Colorful Compact give *every skill chip its own bright
   color* — which fights the discipline the restyled templates adopted.
   (Colorful Compact's whole concept is multicolor, so it gets a documented
   exception — but with a *capped, defined* palette, not "each chip a random
   hue".)

5. **Metadata drifts from reality.** `cvTemplates.js` still calls Developer
   a "dark sidebar" template; the sidebar has been light for weeks.

6. **Near-duplicates.**
   - **Classic vs Classic Professional** — near-identical: serif name,
     uppercase headings over thin rules, icon contact row. Sole difference:
     name alignment (left vs centered). (Modern vs Tech Executive was the
     same story in Aug; resolved by recoloring Modern to rose.)
   - Graduate reads as generic "SaaS card grid" — the exact look Modern
     Professional and Developer were deliberately moved *away from*.

7. **Weak execution on two concepts.**
   - **Quadrant** — the "literal 2×2 grid" idea is distinctive, but the
     top-right cell is mostly dead space, quadrants don't align in height,
     and the cyan accent is near-invisible.
   - **Compact** — visually the weakest of the 16; reads like an unstyled
     default. Its one job (fit one page) is real, but the typography doesn't
     earn it.

8. **Accent-color configurability is inconsistent** — only Timeline and
   Modern Orange expose a Settings swatch; the rest are fixed.

### A.1 — Define the house design language

**Deliverable:** `docs/template-design-system.md` (a real doc in `docs/`,
not a spec — it outlives this cycle). It codifies:

**Type ramp.** One shared scale — `name / title / section-heading /
entry-title / body / meta` — with defined values per **density class**:
`roomy`, `standard`, `compact`. A template picks a class; it does not set
ad-hoc sizes. `compact` is what the Compact template *should* be built on,
and what a "fits one page" mode on other templates would switch to.

**Color rule.** Every template = **1 ink + 1 accent + ≤1 neutral tint**.
Accent is for wayfinding only (dates, rules, section markers, icons) —
never body text, never role/company text. Multicolor is allowed *only*
where it's the template's stated concept (Colorful Compact), and then only
from a **named, capped palette** defined in the doc.

**Section-heading treatments.** A closed menu — e.g. `rule-under`,
`icon-badge`, `left-tick`, `eyebrow-caps`, `numbered`. Each template picks
**one** and uses it everywhere. "icon-badge" stops being the default.

**Shared primitives — identical everywhere, no exceptions:**
- **URLs** — every template + the flat renderer calls `formatLinkDisplayValue()`.
  Add it to Compact, Navy Professional, Modern Timeline, `CVPreview.jsx`.
- **Skills** — define which density class uses chips vs inline-comma-list
  vs dot-rating. Dot-rating only where the concept supports it (Modern
  Orange), always carrying the "derived from list order, stylized, not a
  literal claim" honesty note the memory established.
- **Dates** — one formatter (`formatDateRange` already exists; audit callers).
- **Contact row** — one icon set, one field order.
- **Accent color** — **every template exposes the Settings accent swatch**
  (user confirmed 2026-09-09). Today only Timeline and Modern Orange do.
  A.1 defines the mechanism: each template's CSS reads its accent from one
  CSS custom property with a per-template default; the swatch row in
  `SettingsModal` becomes unconditional; `uiReducer` holds one accent value
  keyed by template id (or one shared value — decide in A.1). Templates
  whose concept is a *fixed* palette (Colorful Compact's rainbow, the
  ink-only Classic/Minimalist) opt out explicitly and the swatch hides for
  them — the default is "configurable", opting out is the exception.

**Structural-variety guardrail.** Document the current structural families:
`single-column-flow`, `single-column-timeline`, `left-rail + main`,
`right-rail + main`, `dark-sidebar + main`, `grid`. A template must be
distinguishable from every other by **structure or a strong distinct
typographic voice**, not accent hue alone. A new template either opens a
new family or is clearly the best-in-class of its family.

**Content edge-case checklist** every template must pass:
long name (verified narrow-column floor — see memory), no photo, 1 job,
10 jobs, missing optional sections, very long single skill, ATS-fallback
parity, PDF export rendered-back-to-image check.

**Export-safety checklist.** Move the hard-won rules out of the work-log
memory and into this doc: no `background-clip:text`; no `clip-path`; hex
colors only in `*.css` and in inline SVG `stop-color` (no `var()`); `filter:blur()`
only on `data-export-ignore="true"` elements; `.pdf-export-root`
duplicates for any `@media print` fallback; no entrance animations that
aren't covered by the global `.pdf-export-root *{animation:none}` rule.

**The quality rubric.** A scored sheet (0–3 per axis): typography,
color discipline, structural clarity, density handling, content
edge-cases, ATS-fallback parity, export fidelity. Every template gets
scored in A.2.

### A.2 — Audit + triage all 16

Score every template against the A.1 rubric; produce a table with a
verdict per template: **keep / polish / rework / merge / retire.**

Retiring and merging templates is **allowed** (user confirmed 2026-09-09 —
the earlier "recolor, don't delete" note no longer binds). The table below
is still confirmed with the user before any template is touched.

Provisional verdicts from the 2026-09-09 pass (to be confirmed with real
scoring):

| Template | Provisional verdict | Note |
|---|---|---|
| Modern Professional | keep | reference-restyled; the current benchmark |
| Modern Orange | keep | premium; minor polish only |
| Navy Professional | polish | strong concept; fix sidebar URL wrap (primitive) |
| Portfolio Hybrid | polish | reconsider the green "Live Demo" button in a CV |
| Minimalist | keep | honest baseline / default; light polish |
| Classic Professional | keep | the "safe traditional" slot |
| Creative | polish | cap the palette — multicolor chips + rainbow bar reads noisy |
| Modern Timeline | polish | URL primitive; add one distinctive move, it's plain |
| Colorful Compact | polish | keep the concept, move to a *named capped* rainbow set |
| Tech Executive | polish | competent but generic corporate-blue |
| Developer | rework | reconcile "dark sidebar" (restore or re-copy); tame links; re-verify gradient-name export |
| Executive | rework | gold accent is invisible; multicolor sidebar chips contradict "restrained boardroom" — commit to mono-gold |
| Graduate | rework | "SaaS card grid" look; monotone indigo — move toward editorial like Modern did |
| Quadrant | rework **or** retire | bold idea, weak execution — fix the dead-space/alignment/accent properly or cut it |
| Compact | rework **or** retire | weakest visual; rebuild on the `compact` density class with real typographic craft, or retire in favour of a one-page toggle on another template |
| Classic | **merge/retire** | near-identical to Classic Professional; fold its left-align in as an option, retire the separate entry |

Rough shape: ~5 keep, ~5 polish, ~4 rework, ~2 retire/merge → **~13–14
strong templates** rather than 16 uneven ones, before A.3 adds any.

### A.3 — Fill genuine gaps with new templates

**Only after A.2.** Each new template clears the A.1 rubric *before* it
ships, and follows the file checklist in the work-log memory (9+ files:
config, Showcase, css, index.css @import, registry+prefetch, cvTemplates
`en`+`fi`, CVPreview lazy+delegation, and — if accent-configurable —
uiReducer/ResumeBuilderPage/SettingsModal; plus the 6 literal "N templates"
strings in `LandingPage.jsx`).

Directions (confirmed with the user 2026-09-09 — all three):
- A **true editorial one-column** — magazine masthead, large type, generous
  measure, no sidebar — distinct from Classic's letterhead restraint.
- A **photo-forward** template — most templates under-use the photo; one
  should make it central.
- A **European one-page standard** — the strict Europass-adjacent format,
  genuinely minimal.

Target: **+3** (one per direction), ending at ~16–17 *strong* templates.
Exact briefs finalized when A.3's own plan is written.

**Editorial one-column DONE (2026-09-13, v1.2.20).** `numbered` heading
treatment + `single-column-flow` family, per §5's own note naming this the
open combination.

**Photo-forward DONE (2026-09-13, v1.2.21) — Portrait.** Opens a new
`photo-rail + main` family (§5): a full-height, full-bleed photo, not a
modest circular avatar alongside rail text. European one-page remains.

### A.4 — Template quick-switcher (the one builder item that lives with A)

The toolbar `TEMPLATE` control is a **carousel** (arrows, ~4 visible at a
time — 4 arrow-clicks to see all 16). The rail's **Templates** item opens
a proper 3-column gallery modal with real thumbnails + descriptions +
"Use template". Two entry points, and the carousel is the weaker one — the
same pattern the font picker had before `todo.md` #49 replaced it with a
plain list. Collapse to one: the toolbar control either opens the gallery
modal directly, or becomes a clean vertical list.

**DONE (2026-09-13, v1.2.19).** Toolbar control now opens the gallery
modal directly — one template picker, not two.

## C. Word (`.docx`) export — scoped, own spec

User's stated direction: **styled `.docx` per template**, not a single
ATS-plain file. Scoped here; detailed spec (`docs/superpowers/specs/<date>-word-export-design.md`)
written after A.1, because the `.docx` layout archetypes must mirror A.1's
structural families.

**Library:** `docx` (npm, MIT, pure-JS, runs in a worker, emits real
OOXML). No headless-office conversion. Lazy-loaded like the PDF path, most
likely assembled in a worker (`src/workers/`), wired into the export menu
as a 4th item "Word (.docx)" with a one-line hint.

**The honest reality of "styled per template":** `.docx` has no
flex/grid. Options for two-column templates: Word *section columns*
(content flows col-1-full then col-2 — bad for a CV) or a **borderless
2-cell table** (workable for sidebar + main). Bespoke flourishes —
timelines, gradient bars, icon badges, dot-ratings — mostly won't
translate; approximate with table borders, cell shading, Unicode marks,
or drop them. "Recognizably the same template," not pixel-matching.

**Phasing:**
- **C1 — ATS-friendly one-column `.docx`.** Real Word styles (Heading 1/2,
  named paragraph styles), genuinely editable, parses perfectly. Ship this
  first regardless of the styled ambition — it's what most `.docx` users
  actually want, and it's the guaranteed fallback for every template.
  **Done v1.2.16:** `exportCvAsDocx`/`buildDocxDocument`
  (`src/utils/docxExport.js`), 20 section builders reusing the PDF
  text-fallback's data-shaping, monochrome/one-column/no-worker, `Word`
  export menu item, `scripts/check-docx-export.mjs` (35 checks). Detailed
  spec: `docs/superpowers/specs/2026-09-11-word-export-c1-design.md`.
- **C2 — styled `.docx` layout mapper.** 3–4 archetypes (one-column,
  left-rail-table, right-rail-table, dark-sidebar-table) mirroring A.1's
  structural families; each bespoke template maps onto one, carrying its
  accent color + heading treatment.
- **C3 — per-template refinement.** An open-ended long tail — **timeboxed**,
  and "approximate" is an accepted outcome.

The user has committed to the full C2 + C3 styled effort (2026-09-09), not
just C1. It still ships in the C1 → C2 → C3 order, and C3 stays timeboxed.

**Risk called out now:** C2/C3 is an unbounded per-template bug tail. The
detailed spec must set a timebox and an explicit "good enough" bar.

## Sequencing

```
A.1  design-system doc + shared primitives (type ramp, color rule, URL helper everywhere)
      └─ foundational; unblocks everything; also closes B2
A.2  audit + triage 16 templates → verdict table → USER SIGN-OFF
B    fold B3–B5 polish in here
A.4  template quick-switcher (= B1)
A-fix  execute polish / rework / retire per A.2 — one template per PR,
       each re-scored + real-PDF-export-checked before merge
C1   ATS-friendly .docx            ── can run parallel with A-fix
A.3  new templates for confirmed gaps
C2 / C3  styled .docx              ── last; archetypes depend on final A structural families
```

Each of **A.2, B, A.4, C1, the A-fix batch, A.3, C2** becomes its own
implementation plan via the writing-plans skill. This doc is the parent.

## Decisions (resolved 2026-09-09)

1. **Retiring / merging templates** — allowed. "Recolor, don't delete" no
   longer binds. Per-template calls still go through the A.2 sign-off.
2. **New templates** — all three directions (editorial one-column /
   photo-forward / European one-page), +3, briefs finalized in A.3's plan.
3. **Word export** — full C1 → C2 → C3 styled effort is in scope; C3 stays
   timeboxed with a "good enough" bar set in C's own spec.
4. **Accent color** — every template gets the Settings swatch by default;
   fixed-palette templates opt out explicitly (see A.1 shared primitives).
