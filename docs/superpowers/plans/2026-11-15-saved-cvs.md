# Saved CVs on the Device Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A visitor can save the CV on their device under a name, have later edits save themselves, and manage several saved CVs, with nothing stored before the first explicit save.

**Architecture:** `cvLibrary.js` wraps IndexedDB and holds the pure naming rules; `useCvLibrary.js` owns the active saved CV, auto-save and the actions; `SavedCvsModal.jsx` is the name prompt and the My CVs list. `ResumeBuilderPage.jsx` wires them to the toolbar, Settings, undo history and the leave guard.

**Tech Stack:** React 19, IndexedDB (no library), Playwright, a Node check script.

**Spec:** `docs/superpowers/specs/2026-11-15-saved-cvs-design.md`

## Global Constraints

- Nothing is written to IndexedDB before the visitor's first explicit save.
- Database `portifycv`, version 1, store `cvs`, keyPath `id`. Session key `portifycv-active-cv`.
- Record: `{ id, name, data, templateId, createdAt, updatedAt }`; times are `Date.now()` numbers.
- A CV read from the library passes through `parseImportedCvData`.
- Every user-facing string in `en` and `fi`.
- New site copy: `No login. Nothing saved unless you choose to.` / `Ei kirjautumista. Mitään ei tallenneta, ellet itse tallenna.`
- Commits carry only the user's name.

## Review Focus

1. Undo after opening another saved CV. Expected: undo is empty; CV A's content can never be auto-saved into CV B.
2. The same CV open in two tabs. Expected: the second writer gets a conflict toast and stops auto-saving; no silent overwrite.
3. A reload of the tab while a saved CV is open. Expected: still attached to it (name shown, edits keep saving).
4. The active record deleted (here, in another tab, or by clearing site data) while open. Expected: the CV stays on screen, becomes "not saved", no error loop.
5. IndexedDB blocked or failing. Expected: Save explains it; editing, export and session restore are unaffected.

### Task 1: Library module

**Files:** Create `src/utils/cvLibrary.js`, `scripts/check-cv-library.mjs`. Modify `package.json` (`check:cv-library`), `.github/workflows/ci.yml`.

**Interfaces — produces:**
- `MAX_CV_NAME_LENGTH = 60`
- `normalizeCvName(name: string): string` — trims, collapses whitespace, cuts to the limit.
- `defaultCvName(data: CvData, locale): string` — `"<fullName> CV"`, or `My CV` / `Oma CV` when the name is empty.
- `nextCopyName(name: string, existingNames: string[], locale): string` — `Name (copy)`, then `Name (copy 2)`…; Finnish `(kopio)`; never longer than the limit; case-insensitive against existing names.
- `createCvRecord({ name, data, templateId, now, id? }): CvRecord`
- `isCvLibraryAvailable(): boolean`
- `listSavedCvs(): Promise<Array<{ id, name, templateId, createdAt, updatedAt }>>` newest first.
- `getSavedCv(id): Promise<CvRecord | null>`
- `saveCv(record, { expectedUpdatedAt }): Promise<CvRecord>` — `expectedUpdatedAt: null` means "must not exist yet"; `undefined` means overwrite. Throws an `Error` with `code: 'conflict'` on a mismatch, `code: 'missing'` when an expected record is gone, `code: 'unavailable'` when IndexedDB cannot be used.
- `renameSavedCv(id, name)`, `deleteSavedCv(id)`, `clearSavedCvs()`, `countSavedCvs()`.

- [ ] Write `check-cv-library.mjs` for the pure functions (names, copy numbering in both locales, length limit, record shape, `isCvLibraryAvailable()` false in Node). Run: fails on the missing module.
- [ ] Implement. Run `npm run check:cv-library`, `npm run lint`. Commit `Add the saved-CV library module and check:cv-library`.

(The IndexedDB calls are exercised by Task 4's e2e spec.)
